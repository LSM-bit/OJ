# 管理后台设计：管理员角色区分 + 后台管理界面

> 编写日期：2026-09-07
> 状态：**已实现（一期）**——后端 /admin 全组接口、submissions.code 迁移、前端 8 页均已落地并通过验证矩阵
> 关联：docs/权限模型设计.md、docs/项目计划.md 第 3.8 节（管理后台）

---

## 1. 目标

1. **区分普通用户与管理员**：现有 `UserRole` 已有四级（USER / PROBLEM_SETTER / CONTEST_ADMIN / ADMIN），本设计明确各级在后台的权限边界
2. 管理员可查看/操作**系统后台**：用户、题目、比赛、题单、团队、提交、判题节点监控
3. 后台是**独立界面区**（`/admin/*` 路由 + 独立布局），与前台页面隔离
4. 权限校验复用统一模式：后端依赖工厂 `AdminAccess`，前端路由守卫 + 菜单只做入口控制

---

## 2. 角色权限矩阵

现有四级角色在后台的权限（ADMIN 恒超集）：

| 后台功能 | USER | PROBLEM_SETTER | CONTEST_ADMIN | ADMIN |
|---|---|---|---|---|
| 用户管理（列表/封禁/改角色） | ✗ | ✗ | ✗ | ✓ |
| 题目管理 | 仅自己的 | 自己的 + 团队的 | 仅自己的 | **全部** |
| 题目数据上传/重判 | 仅自己的 | 自己的 + 团队的 | ✗ | 全部 |
| 比赛管理 | 仅自己的 | 仅自己的 | 自己的 + 团队的 | 全部 |
| 题单管理 | 仅自己的 | 自己的 + 团队的 | 自己的 + 团队的 | 全部 |
| 团队管理（解散/改名） | 仅自己是队长的 | 同左 | 同左 | 全部 |
| 提交管理（查看所有提交/重判） | 仅自己的 | ✗ | 比赛内全部 | **全部** |
| 判题节点监控 | ✗ | ✗ | ✗ | ✓ |
| 站点概况（Dashboard） | ✗ | ✗ | ✗ | ✓ |

> 设计原则：**"全部"类操作仅 ADMIN**；其他角色在后台只看到"我管理的资源"视图（即把前台的 owner 过滤逻辑复用，`can_manage` 为 true 的资源）。
> 二期可引入 `ADMIN` 细分（如 `USER_ADMIN` / `JUDGE_ADMIN`），字段留枚举扩展即可。

## 2.1 前端角色区分

- 顶栏：管理员显示"后台"入口；普通用户不显示
- 前端 `isAdmin = user.role === 'admin'`；`isSetter = ['problem_setter','admin'].includes(role)` 等辅助判断
- 路由守卫：`/admin/*` 下 meta `{ requiresAdmin: true }`，非 ADMIN 跳首页（但真正的校验在后端，前端只是体验层）

## 3. 后台信息架构（页面规划）

独立布局：左侧菜单 + 顶部面包屑（复用现有 Element Plus 风格）

```
/admin                 → Dashboard（站点概况）
/admin/users           → 用户管理
/admin/problems        → 题目管理（全部题目，含私有）
/admin/contests        → 比赛管理
/admin/playlists       → 题单管理
/admin/teams           → 团队管理
/admin/submissions     → 提交管理
/admin/judges          → 判题节点监控
```

### 3.1 Dashboard `/admin`
- 顶部统计卡：用户数、今日提交数、通过率、在线判题节点数、等待队列长度
- 中部：最近 7 天提交趋势（简单柱状，二期上图表库）
- 侧栏：最近提交列表（滚动）、异常节点告警

### 3.2 用户管理 `/admin/users`
- 列表：id、用户名、邮箱、角色、Rating、状态（正常/封禁）、注册时间
- 操作：改角色（下拉）、封禁/解封、重置密码（二期）
- 搜索：按用户名/邮箱

### 3.3 题目管理 `/admin/problems`
- 全量题目列表（**含私有**，列表接口加 `scope=all` 参数，仅 ADMIN）
- 显示：题号、标题、归属（个人/团队/私有标记）、数据版本、测试点数、通过率
- 操作：编辑（跳题面编辑）、数据管理（上传/重传数据包）、设为公开/私有、删除（软删，二期）

### 3.4 比赛管理 `/admin/contests`
- 全量比赛列表（含私有/未开始/已结束）
- 操作：编辑信息、改公开/私有、强制结束、重算榜单、重判整场比赛

### 3.5 题单管理 `/admin/playlists`
- 全量题单 + 操作：编辑、调整公开性、删除

### 3.6 团队管理 `/admin/teams`
- 全量团队：名称、队长、人数、创建时间
- 操作：解散、查看成员

### 3.7 提交管理 `/admin/submissions`
- 全站提交流：id、用户、题目、语言、状态、耗时/内存、时间（实时刷新，5s 轮询）
- 筛选：按状态/题目/用户/比赛
- 操作：查看详情（含错误输出全文）、**单条重判**

### 3.8 判题节点监控 `/admin/judges`
- 节点卡片：node_id、名称、状态（在线/离线）、当前运行数/容量、最后心跳
- 队列信息：等待任务数
- 数据源：`GET /admin/judges`（聚合 `health/judges` + 网关内部状态，需 ADMIN）

## 4. 后端 API 设计

新增 `api/app/routers/admin.py`，统一前缀 `/admin`，整组挂 ADMIN 依赖：

```python
router = APIRouter(prefix="/admin", tags=["admin"],
                   dependencies=[Depends(require_admin)])
```

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/overview` | Dashboard 统计：用户数/今日提交/AC 率/队列长度 |
| GET | `/admin/users` | 用户列表（分页 + 搜索） |
| PUT | `/admin/users/{id}/role` | 修改角色 |
| PUT | `/admin/users/{id}/ban` | 封禁/解封 body {banned: bool} |
| GET | `/admin/problems` | 全量题目（含私有 + 测试点数 + 通过率） |
| PUT | `/admin/problems/{id}` | 编辑（公开性等） |
| DELETE | `/admin/problems/{id}` | 删除（一期校验无提交记录才允许） |
| GET | `/admin/contests` | 全量比赛 |
| PUT | `/admin/contests/{id}` | 编辑/强制结束 |
| POST | `/admin/contests/{id}/rejudge` | 重判整场比赛（二期，队列支持后） |
| GET | `/admin/playlists` | 全量题单 |
| DELETE | `/admin/playlists/{id}` | 删除题单 |
| GET | `/admin/teams` | 全量团队 |
| DELETE | `/admin/teams/{id}` | 解散团队 |
| GET | `/admin/submissions` | 全站提交（分页 + 状态/题目/用户筛选） |
| POST | `/admin/submissions/{id}/rejudge` | 单条重判 |
| GET | `/admin/judges` | 节点状态聚合（含队列深度、节点容量占用） |

### 4.1 权限依赖

```python
# services/auth.py 增加
def require_admin(user: User = Depends(get_current_user)) -> User:
    if user.role != UserRole.ADMIN:
        raise HTTPException(status.HTTP_403_FORBIDDEN, "需要管理员权限")
    return user
```

- `/admin/*` 整组强校验，不依赖前端路由
- 普通业务接口保持现状（资源级 `can_manage` 已覆盖 ADMIN 超集行为）

### 4.2 重判机制（一期简化版）

- 单条重判：提交记录的 code 需要留存才能重判。当前 code 只透传给判题机未落库
  → **一期先给 submissions 表加 `code` 字段**（TEXT，存源码；二期迁对象存储）
- 重判 = 重新组装 SubmitJob → 走网关 → 覆盖结果字段（status/score/time/memory/detail）
- 整场比赛重判 = 遍历该比赛 submissions 逐条重发（高峰期限流，一期不做并发）

### 4.3 网关状态暴露

`gateway.py` 增加只读快照方法：

```python
def snapshot(self) -> dict:
    """节点列表(含 running/capacity/last_seen) + 等待队列长度 + pending 数"""
```

`/admin/judges` 直接读该快照，不新增 gRPC 往返。

## 6. 前端实现规划

### 6.1 结构

```
web/src/
├── views/admin/
│   ├── AdminLayout.vue      # 后台框架（左侧菜单 + 内容区）
│   ├── DashboardView.vue    # /admin
│   ├── AdminUsers.vue       # /admin/users
│   ├── AdminProblems.vue    # /admin/problems
│   ├── AdminContests.vue    # /admin/contests
│   ├── AdminPlaylists.vue   # /admin/playlists
│   ├── AdminTeams.vue       # /admin/teams
│   ├── AdminSubmissions.vue # /admin/submissions
│   └── AdminJudges.vue      # /admin/judges
```

### 6.2 路由与守卫

```ts
// router/index.ts
{
  path: '/admin',
  component: () => import('../views/admin/AdminLayout.vue'),
  meta: { requiresAdmin: true },
  children: [
    { path: '', name: 'admin-dashboard', component: () => import('../views/admin/DashboardView.vue') },
    { path: 'users', ... }, { path: 'problems', ... }, ...
  ],
}

// 守卫
router.beforeEach((to) => {
  if (to.meta.requiresAdmin && userStore.user?.role !== 'admin') return '/'
})
```

- App.vue 顶栏：`v-if="userStore.user?.role === 'admin'"` 显示"后台"菜单项
- 后台刷新后 fetchMe 已有（App.vue onMounted），守卫时序安全

### 6.3 各页面复用组件

- 统一 `AdminTable` 模式：搜索栏 + 表格 + 分页 + 行内操作（各页差异只在新列表页里）
- 提交管理页 5 秒轮询刷新（一期不引 WebSocket）
- Dashboard 统计卡直接 flex 布局，不引图表库（二期需要再说）

## 8. 验证矩阵

| 场景 | 期望 |
|---|---|
| 普通用户访问 /admin/users | 前端跳首页；直接调 API 403 |
| PROBLEM_SETTER 调 /admin/problems | 403（后台接口仅 ADMIN） |
| ADMIN 看题目管理列表 | 含私有题目，带归属标记 |
| ADMIN 封禁用户 | 该用户现有 token 立即失效（get_current_user 已查 banned） |
| ADMIN 改某用户角色为 problem_setter | 该用户下次请求即有出题权限 |
| 单条重判 AC 提交 | 状态/耗时/内存刷新 |
| 重判 code 为空的历史提交 | 400 提示不支持 |
| /admin/judges 无节点在线 | 显示离线，等待队列长度可见 |
| 前端 /admin 直接输 URL（非管理员） | 守卫跳首页 |
