# 管理后台：ADMIN 权限 + 后台管理界面（已实现）

> 编写日期：2026-09-07（设计稿）｜ 最近更新：2026-09-16（按阶段 8 后现状重写）
> 状态：**已实现**——后端 `/admin` 全组接口 + 前端 12 个页面全部落地；本文按实际形态纪实，与设计稿的差异见 §10
> 关联：docs/权限模型设计.md（角色体系）、docs/AI助手Agent设计.md（用量看板数据源）

---

## 1. 目标（兑现情况）

1. **区分普通用户与管理员** ✅——但落地为**两级角色**（USER/ADMIN），设计稿预设的四级（含 PROBLEM_SETTER/CONTEST_ADMIN）未采用，出题/建赛对登录用户放开，靠资源级权限约束；
2. 管理员可查看/操作用户、题目、比赛、题单、团队、提交、判题节点 ✅，另加了设计外的**标签管理、AI 用量看板、公告管理**；
3. 后台是**独立界面区**（`/admin/*` 路由 + AdminLayout 左侧菜单）✅；
4. 权限校验复用统一模式：后端 `require_admin` 组级依赖 + 前端路由守卫只做入口控制 ✅。

## 2. 权限边界（现状）

| 后台功能 | USER | ADMIN |
|---|---|---|
| 用户管理（列表/改角色/封禁） | ✗ | ✓ |
| 题目/比赛/题单/团队 全量列表 | ✗（前台只见"我可管理的"） | ✓ |
| 提交管理（全站 + 单条重判 + 按题批量重测在比赛路由） | ✗ | ✓ |
| 标签管理 | ✗ | ✓ |
| 判题节点监控 | ✗ | ✓ |
| AI 用量看板 | ✗ | ✓ |
| 公告管理（发布/编辑/置顶/删除） | ✗ | ✓ |
| 站点概况 Dashboard | ✗ | ✓ |

- 原设计"中间角色在后台只看我管理的资源"不再需要——「我管理的资源」视图就是前台本体（题目列表 `?mine=1` 等），后台只为 ADMIN 全量视图而存在；
- 后端 `/admin` router 整组 `dependencies=[Depends(require_admin)]`，不依赖前端；普通业务接口维持资源级 `can_manage`（ADMIN 恒超集）。

### 2.1 前端入口控制

- 顶栏：`userStore.user?.role === 'admin'` 显示「后台」入口；
- 路由守卫：`/admin/*` 整组 `meta: { requiresAdmin: true }`，非 ADMIN 跳首页（体验层；真正校验在后端）；
- ADMIN 改角色下拉现只有 user/admin 两项。

## 3. 页面清单（12 页）

```
/admin                 → DashboardView        站点概况
/admin/users           → AdminUsers           用户管理（搜索/改角色/封禁）
/admin/problems        → AdminProblems        题目管理（全量含私有；公开性/删除）
/admin/tags            → AdminTags            标签管理（新建/重命名同步替换/删除）
/admin/contests        → AdminContests        比赛管理（全量列表）
/admin/playlists       → AdminPlaylists       题单管理（全量列表）
/admin/teams           → AdminTeams           团队管理（全量列表）
/admin/submissions     → AdminSubmissions     提交管理（筛选 + 详情 + 单条重判）
/admin/judges          → AdminJudges          判题节点监控（在线/容量/心跳/队列）
/admin/ai-usage        → AdminAiUsage         AI 用量看板（echarts）
/admin/announcements   → AdminAnnouncements   公告管理（发布/编辑/置顶/删除）
```

各页共享 AdminLayout（左菜单 + 右 `<router-view/>`）；列表页统一「搜索栏 + el-table + 行内操作」模式，无独立 AdminTable 抽象（各页差异小，直接内联，与标签/公告页同构）。

### 3.1 Dashboard

统计卡（用户数/题目数/今日提交/AC 率/在线节点）+ 最近提交；数据源 `GET /admin/overview`。

### 3.2 用户管理

搜索用户名/邮箱分页；`PUT /admin/users/{id}/role`（自己不能改自己）、`PUT /admin/users/{id}/ban`（封禁即时生效——`get_current_user` 每次查 banned，现有 token 立即失效）。

### 3.3 题目管理

全量题目（含私有、归档），显示归属（个人/团队）、数据版本、测试点数；操作：编辑跳转、公开性切换、删除（有提交记录则拒绝）。「按题批量重测」在比赛管理侧（contests 路由的 rejudge），后台提交页只做单条。

### 3.4~3.6 比赛/题单/团队管理

全量列表（`GET /admin/contests|playlists|teams`）——这三页以**看**为主（含私有/归档），管理动作仍在前台资源所有者的编辑页进行（ADMIN 超集自然可进）；团队页可解散。

### 3.7 提交管理

全站提交流（状态/题目/用户/比赛筛选）；详情含代码与逐点结果；**单条重判** `POST /admin/submissions/{id}/rejudge`——前提：submissions 表有 `code` 列（迁移已做，提交时落库源码）；code 为空的存量旧提交返回 400「不支持重判」。重判 = 重组 SubmitJob 走网关覆盖结果字段。

### 3.8 判题节点监控

节点卡片（node_id/名称/在线/running/capacity/最后心跳）+ 等待队列深度；数据源 `GET /admin/judges` 读网关 `snapshot()` 只读快照，零 gRPC 往返。

### 3.9 标签管理

`/admin/tags` CRUD——重命名同步替换所有题目 tags 数组（返回 touched 计数）；删除从题目 tags 移除；出题表单标签弹窗共用此词表。

### 3.10 AI 用量看板（设计外新增）

`GET /admin/ai-usage?days=14`（ge=1 le=90，越界钳制）→ 后端 Python 侧分桶聚合（测试库 SQLite，避开 date_trunc 方言）：

```json
{ "totals": {"rounds","users","input_tokens","output_tokens","tool_calls"},
  "daily":  [{"date","rounds","input_tokens","output_tokens"}],   // 连续日期补零
  "tools":  [{"tool","count"}],
  "top_users": [{"user_id","username","rounds"}] }                // 前 10
```

数据源：`assistant_messages`（join conversation 按日 count user 行 = 轮数、累加 assistant 行 token）+ `assistant_tool_calls`（工具分布）。前端 echarts（^6.1.0）按需引入（`echarts/core` + Line/Bar + CanvasRenderer）：顶部 5 张统计卡 + 双 y 轴折线（轮数/token）+ 工具分布横向柱 + Top 用户表格；7/14/30/90 天切换；组件路由懒加载，echarts 天然切独立 chunk，vite 配置未动。

### 3.11 公告管理（本次新增）

管理员在后台发布/维护全站公告（前台主页左侧公告栏展示，未登录也可读）：

- 后端复用既有 `/misc/announcements` 三端点 + 新增 **`PUT /misc/announcements/{id}`**（编辑标题/正文/置顶，只覆盖显式传入字段）；POST/DELETE 本就 `require_admin`；
- 前端 AdminAnnouncements.vue：列表（读 `GET /misc/announcements?limit=50`，前端本地搜索标题/内容）+ 发布/编辑弹窗（textarea autosize）+ 行内置顶切换与删除确认；
- 置顶公告排最前（`top.desc(), created_at.desc()`）。

## 4. 后端 API 汇总（`api/app/routers/admin.py`，实测 20 端点）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/overview` | 站点概况统计 |
| GET | `/admin/users` | 用户列表（分页+搜索） |
| PUT | `/admin/users/{id}/role` · `/ban` | 改角色 / 封禁解封 |
| GET/PUT/DELETE | `/admin/problems[/{id}]` | 全量题目 / 编辑 / 删除 |
| GET/POST/PUT/DELETE | `/admin/tags[/{id}]` | 标签 CRUD（重命名/删除带 touched） |
| GET | `/admin/contests` · `/playlists` · `/teams` | 全量列表 |
| GET | `/admin/submissions` · `/{id}` | 全站提交 / 详情 |
| POST | `/admin/submissions/{id}/rejudge` | 单条重判 |
| GET | `/admin/judges` | 节点快照 |
| GET | `/admin/ai-usage` | AI 用量聚合（§3.10） |

公告端点在 `/misc` 组（`routers/misc.py`），写操作逐个 `require_admin`。

## 6. 前端结构

```
web/src/views/admin/          11 个业务页 .vue（§3 清单含 Dashboard 共 12 路由）+ AdminLayout.vue
web/src/router/index.ts       /admin 父路由 meta.requiresAdmin + 11 个 children（'' 为 Dashboard）
```

提交管理页 5s 轮询刷新（一期不引 WebSocket）；Dashboard 与公告页纯 CSS/Element，不引图表库——全站唯一 echarts 消费者是 AI 用量看板。

## 10. 设计稿 → 实际的差异汇总

| 设计稿 | 实际 | 原因 |
|---|---|---|
| 四级角色各自后台视图 | 两级，后台仅 ADMIN | 中间角色与资源级权限重复（docs/权限模型设计.md §3） |
| 「我管理的资源」后台视图 | 前台 `?mine=1` 已覆盖，不重复做 | 同上 |
| 比赛管理含强制结束/改公开性 | 后台只列，动作在前台编辑路由 | ADMIN 过 can_manage 天然可编辑 |
| Dashboard「二期上图表库」 | 全站概况仍纯 CSS；echarts 只进 AI 看板 | 按需引入，独立 chunk |
| 8 页 | 12 页（+标签/AI 用量/公告；归档视图等散布前台） | 阶段 5~8 自加功能 |
