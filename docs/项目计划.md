# OJ（Online Judge）在线评测系统 · 项目计划

> 参考对象：牛客 OJ、QOJ（HydroOJ 生态）、Codeforces、洛谷
> 定位：**面向公网运营**的算法竞赛在线评测平台
> 后端技术栈：**Python 系**（FastAPI）
> 编写日期：2026-09-07

---

## 1. 项目目标

### 1.1 一期目标（MVP → 可公网运营）
- 用户可以注册登录、刷题、提交代码、查看判题结果
- 支持 ACM / OI 赛制的比赛，含实时榜单、封榜
- 有基础社区（讨论区、题解）与训练系统（题单、打卡）
- 判题机支持 C/C++/Java/Python 等主流语言，**沙箱安全隔离**（公网运营红线）

### 1.2 二期目标
- Special Judge、Subtask/子任务计分、交互题、文件 IO 题型
- Rating 积分体系（类 Codeforces Elo）
- 防作弊：代码查重（SIM/WINNOWING）、比赛行为审计

## 2. 总体架构

```
┌─────────────┐     ┌──────────────────────────┐
│  前端 Web    │────▶│  后端 API 服务 (FastAPI)  │
│  Vue3/React │     │  (无状态, 可水平扩展)      │
└─────────────┘     └───────┬──────────┬───────┘
                            │          │
                    ┌───────▼───┐  ┌───▼────────┐
                    │ PostgreSQL │  │   Redis    │
                    │ (业务数据) │  │ (缓存/会话/ │
                    └───────────┘  │  限流/榜单) │
                                   └────────────┘
                            │
                    ┌───────▼────────┐
                    │  消息队列       │   判题任务分发
                    │ (Redis Stream  │◀──────┐
                    │  或 RabbitMQ)  │       │
                    └───────┬────────┘       │
                            │                │
                 ┌──────────▼───────────┐    │
                 │  判题机 Judge ×N      │────┘
                 │  (独立部署, 可加机器) │
                 │  go-judge 沙箱       │
                 └──────────┬───────────┘
                            │
                 ┌──────────▼───────────┐
                 │  对象存储 (MinIO/OSS) │  测试数据/提交代码
                 └──────────────────────┘
```

**核心设计原则**
1. **Web 服务与判题机彻底分离**：判题机不暴露公网，只通过队列/内网与 API 通信，这是安全底线（参考 QOJ / Hydro 的 judge-client 架构）。
2. **判题机无状态、可水平扩展**：比赛高峰时直接加判题机节点。
3. **所有用户代码必须进沙箱执行**：禁止任何形式的主机直接执行。

## 3. 模块划分

### 3.1 用户模块
| 功能 | 说明 |
|------|------|
| 注册/登录 | 邮箱注册、JWT 或 Session；登录限流防爆破 |
| 个人主页 | 头像、简介、通过题目数、提交数、AC 榜、Rating 曲线 |
| 权限 RBAC | 普通用户 / 出题人 / 比赛管理员 / 超级管理员 |
| 关注/动态 | 二期可选 |

### 3.2 题目模块
| 功能 | 说明 |
|------|------|
| 题目列表/详情 | 题号、标题、标签、难度、时间/空间限制、AC/提交比 |
| 题目管理 | 出题人后台：题面（Markdown + LaTeX 公式）、样例编辑、测试数据上传（.in/.out 打包） |
| 题单 | 官方题单 + 用户自建题单，训练打卡 |
| 统计 | 每题通过率、各测试点通过情况（仅管理员/题主可见） |
| 数据安全 | 测试数据仅判题机可读，用户永远无法下载 .in/.out |

### 3.3 提交与判题模块（核心）
| 功能 | 说明 |
|------|------|
| 代码提交 | 语言选择、提交前校验频率限制 |
| 判题状态 | Waiting → Judging → AC/WA/TLE/MLE/RE/CE/SE |
| 判题详情 | 每个测试点的耗时、内存、得分（OI 赛制）；错误输出前若干字节（比赛外可见） |
| 重新判题 | 管理员对某题/某场比赛全部重判 |
| 代码查看 | 提交者本人、管理员；比赛进行中仅本人可见 |
| 判题机本体 | 见第 4 节专项设计 |

### 3.4 比赛模块（一期重点）
| 功能 | 说明 |
|------|------|
| 赛制 | ACM（罚时排名）/ OI（部分分）/ IOI（子任务，二期） |
| 比赛生命周期 | 未开始 → 报名中 → 进行中 → 已结束（含试玩/练习赛） |
| 实时榜单 | 排名、罚时、每题状态气泡（×/✓/+n）；Redis 存储实时计算 |
| 封榜 | 比赛最后 1 小时冻结榜单，结束后统一揭晓 |
| 比赛题目集 | 题目权限随比赛动态开关，赛中禁止看他人提交 |
| 澄清/公告 | 比赛内公告板、选手提问（牛客风格） |
| 赛后 | 题目转公开始练、AC 代码公示、发题解 |

### 3.5 训练模块（一期）
| 功能 | 说明 |
|------|------|
| 训练计划 | 按专题组题（如「二分专题 15 题」），进度追踪 |
| 打卡 | 每日做题记录、连续打卡统计 |
| 能力雷达 | 按标签统计掌握度（如 dp/图论/数据结构） |

### 3.6 社区模块（一期）
| 功能 | 说明 |
|------|------|
| 讨论区 | 节点式版块（求助/分享/灌水），Markdown + LaTeX |
| 题解 | 每题独立题解区，用户发布 + 点赞，官方题解置顶 |
| 评论/回复 | 两级评论、@ 通知 |
| 内容审核 | 敏感词过滤、举报、管理员置顶/删除 |

### 3.7 通知模块
站内通知（判题完成、@我、回复、比赛开始前提醒）+ WebSocket 实时推送；邮件用于注册验证与找回密码。

### 3.8 管理后台
- 用户管理（封禁、权限）、题目审核流、比赛配置
- 判题机监控：队列积压、节点存活、平均判题耗时
- 站点配置：语言列表、默认限制、公告

### 3.9 防作弊模块（二期，但公网运营需预留）
- 代码查重：WINNOWING / SIM 指纹比对（比赛结束后批量跑）
- 提交行为记录：IP、时间序、浏览器指纹，异常提交审计

## 4. 判题机专项设计（技术核心）

### 4.1 沙箱选型
**推荐 go-judge（原 executor api）**——QOJ/Hydro 同款沙箱：
- cgroup + namespace 双重隔离，内存/时间精确计量
- HTTP/gRPC 接口调用，与 Python 判题服务解耦良好
- 支持 copyIn/copyOut 管道交互（为二期交互题铺路）

备选：NSJail + 手写计量（工作量大，不推荐首选）。

### 4.2 判题流程
```
API 收到提交 → 写入 DB(status=Waiting) → 推入队列
判题机拉取任务 → 从对象存储拉取代码+测试数据
  → 编译(沙箱内, 限时) → CE? 结束
  → 逐测试点运行(沙箱, rlimit+cgroup)
  → 与标准输出比对(忽略行尾空格/末尾换行, 可配置)
  → 汇总结果 → 回写队列 → API 更新 DB + WebSocket 通知用户
```

### 4.3 判题机与 API 通信协议
- 方向：判题机主动**拉取**任务（或长轮询/WebSocket），判题机无需公网 IP
- 消息内容：submission_id、题目配置（限制、SPJ 标记）、语言标识
- 安全：判题机用 token 向 API 认证拉取测试数据，防止数据泄露

### 4.4 判题规则细节（容易踩坑，提前定义）
| 项 | 约定 |
|----|------|
| 计时 | 用户程序墙钟 vs CPU 时间，取 CPU 时间为准、墙钟兜底 |
| 浮点误差 | 支持 `_ Relative Error` / `_ Absolute Error` 判题配置（QOJ 风格） |
| 特判 SPJ | 二期；一期预留 judge 结果字段 `score` 与 `verdict` 分离 |
| 末尾空白 | 默认忽略行尾空格与文件末尾换行 |
| 优化开关 | C++ 默认 `-O2`，支持题目级编译参数覆盖 |

## 5. 技术选型汇总

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue 3 + TypeScript + Pinia + Element Plus | 国内生态成熟，Markdown/LaTeX 渲染组件齐全 |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2 + Pydantic v2 | 异步高性能、自动 OpenAPI 文档 |
| 数据库 | PostgreSQL 16 | JSONB 存题目配置、事务可靠 |
| 缓存/榜单 | Redis 7 | 实时榜单 ZSET、限流、WebSocket 广播 |
| 队列 | Redis Stream（一期）→ RabbitMQ（量大后迁） | 判题任务分发，至少一次投递 |
| 沙箱 | go-judge | 见第 4 节 |
| 存储 | MinIO（自建）/ 阿里云 OSS | 测试数据、代码快照 |
| 部署 | Docker Compose（一期）→ K8s（规模化后） | 判题机用独立镜像 |
| 实时通信 | WebSocket | 判题结果推送、比赛榜单刷新 |

## 8. 关键风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| **沙箱逃逸**（公网最大风险） | ★★★ | 用久经考验的 go-judge，不自己写沙箱；判题机部署在独立内网段，只出不进；定期安全审计 |
| 比赛高峰判题积压 | ★★★ | 判题机水平扩展；队列监控告警；封榜期间人工预热 |
| 测试数据泄露 | ★★ | 数据仅判题机持有 token 拉取；API 层永不返回数据内容 |
| Python 判题调度性能 | ★ | 判题调度只做 IO 和编排，重活全在沙箱/子进程 |
| 资源成本 | ★ | 判题机按需扩容；编译缓存（相同代码哈希复用编译结果） |

## 9. 仓库结构规划

```
OJ/
├── web/        # Vue3 前端
├── api/        # FastAPI 后端
│   ├── app/
│   │   ├── models/      # SQLAlchemy 模型
│   │   ├── routers/     # user / problem / contest / community ...
│   │   ├── services/
│   │   └── tasks/       # 队列消费者

└── docs/       # 本文档、API 文档、判题规则文档
```
